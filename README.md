# DhuStore 东华购物 · 项目介绍

> 一个前后端分离的一站式购物商城，支持**用户购物**、**用户申请发布商品**、**管理员审核与运营**，**首页轮播、促销位与分类图标均可在后台自助配置**，并接入**阿里云 OSS 多图上传**。

---

## 一、项目概览

| 项目 | 说明 |
|---|---|
| 项目名称 | DhuStore（东华购物） |
| 项目类型 | B2C 商城 + 用户发布（C2C）扩展 |
| 架构模式 | 前后端分离（RESTful API + 静态前端） |
| 后端 | Spring Boot 4.1.1 / Java 17 |
| 前端 | Vue 3（CDN 引入，原生 JS 模块）+ 原生 SVG 图表 |
| 数据库 | MySQL 8 |
| 图片存储 | 阿里云 OSS（可回退本地磁盘） |
| 鉴权 | JWT 无状态鉴权 + 角色（普通用户 / 管理员） |

### 角色与能力

| 角色 | 能力 |
|---|---|
| 游客 | 浏览分类与商品、搜索、查看商品详情 |
| 普通用户 | 注册登录、购物车、收货地址、下单支付、订单流转、申请发布商品、查看审核结果 |
| 管理员 | 数据看板、商品管理、分类管理、订单管理与发货、商品发布申请审核、首页内容运营（轮播 / 促销位 / 分类图标） |

## 二、核心功能

### 2.1 商城购物

- **首页**：轮播（后台可配，最多 5 张，无图时展示占位）、分类入口（16:9 场景图卡，后台可配封面）、限时秒杀（后台可配，未配置时自动取品）、商品推荐（等高栅格）
- **首页分类折叠**：默认只露出前两排 + 第三排上半，第三排自上而下淡出，中央叠加「展示全部」；点击展开完整分类并转为「收起」，分类不超过两排时不折叠
- **商品**：分类筛选、关键词搜索（含搜索联想）、分页列表、详情多图浏览
- **购物车**：加购、改数量、勾选/全选、删除、批量删除
- **结算**：选择收货地址、支付方式、订单备注
- **订单**：下单、支付、取消（归还库存）、确认收货、再次购买
- **下单事务**：扣减库存与创建订单在同一事务内，库存不足自动回滚

### 2.2 用户发布商品（C2C 扩展）

核心原则：**用户提交的商品 ≠ 正式商品**。

```
用户填写商品信息 + 上传 1~9 张图片
        ↓
提交申请 → product_apply / product_apply_image
        ↓
管理员审核
   ├── 拒绝：保留记录 + 拒绝原因，用户可查看
   └── 通过（事务）：创建 product + 复制图片到 product_image
                     ↓
                  商品正式上架，记录 seller_id 归属
```

- 商品归属：审核通过时写入 `product.seller_id = 申请人`
- 审核防重：已审核的申请再次审核会被拒绝（业务码 `2005`）

### 2.3 商品多图

- 每个商品 **1~9 张**图片（前后端双重校验）
- 图片按 `sort` 排序，**第一张即主图**
- 详情页支持大图 + 缩略图切换
- 图片存储走 `product/年/月/uuid.ext` 目录，避免扁平化堆积

### 2.4 后台管理

- **数据看板**：销售额/订单量/客单价/新增用户 KPI、销售趋势（SVG 折线）、分类销售占比、订单状态分布、热销 Top5
- **商品管理**：搜索、分类筛选、新增/编辑/删除、图片上传
- **订单管理**：全量订单列表、状态筛选、发货（1→2）
- **发布申请**：申请列表、审核弹窗、通过/拒绝
- **分类管理**：图标上传、新增/编辑/删除，删除前校验该分类下无商品
- **首页图片**：轮播图（≤5 张）与两个促销位的图片配置
- **限时秒杀**：秒杀位商品的添加 / 替换 / 移除，上限 8 个，首页按顺序展示前 4 个

### 2.5 首页内容运营

首页的轮播图、两个促销位（全部商品 / 新人礼包）与分类图标全部由后台配置，不再写死在前端代码里。

| 位置 | 数量 | 存储 | 未配置时 |
|---|---|---|---|
| 首页轮播 | 最多 5 张 | `banner` 表 | 渲染 5 张空白占位，圆点与自动切换照常 |
| 促销位 | 固定 2 个 | `site_setting` 键值 | 回落为内置渐变卡片 |
| 分类图标 | 每个分类 1 张 | `category.icon` | 回落为按名称匹配的内置图形 |
| 分类封面 | 每个分类 1 张（16:9） | `category.cover` | 回落为按分类色相生成的柔和渐变 |
| 限时秒杀 | 最多 8 个（首页展示 4 个） | `flash_sale` 表 | 回落为按库存自动取前 4 件 |

- 图片统一走 `POST /api/common/upload`，数据库只存 URL
- 轮播按 `sort` 升序展示，已有 5 张时新增返回业务码 `2011`
- 促销位采用「草稿 + 显式保存」：选图即时预览，点保存才落库
- 图片态下点击区域仍是整张卡片，跳转目标固定在前端常量，换图不影响链接
- 秒杀位只存**商品引用**不存快照，商品改价、库存变化、下架都会实时反映到首页
- 秒杀位可放至 8 个，首页一屏展示前 4 个；重复添加返回 `2014`，超限返回 `2015`
- 分类封面传空串表示清除、回落到色相渐变，传 `null` 表示保持原值

### 2.6 个人中心

- 资料修改：昵称 / 手机号 / 邮箱，带长度校验
- 头像上传：选图后本地即时预览，点保存才上传并与账号绑定；支持移除（提交空值清除）
- 支持 JPG / PNG / WEBP，单张 ≤ 5MB，格式与大小在前后端双重校验
- 头像在**页头、个人中心侧栏、后台**三处同步：页头优先渲染图片，未设置头像时回落为昵称首字

#### 资料页版式

个人中心为左栏身份卡 + 导航、右栏内容区的两栏结构。资料页按四段纵向排布，段与段之间以留白和分隔线区分，不再把头像、表单、按钮平铺在同一层：

| 区块 | 结构 | 关键参数 |
|---|---|---|
| 页头 `.uc-hd` | 页面标题 + 一行说明 | 标题 18 / 700，说明 12.5 / `--ink-3` |
| 身份区 `.uc-ident` | 84px 圆形头像 + 昵称/角色标签/账号 + 操作按钮 | 底部 1px `--line-2` 分隔，与表单区切开 |
| 表单区 `.uc-sec` | 「基本信息」「联系方式」两组，每组两列 | 组标题前置 3×13 品牌色竖条；说明文字右对齐，12 / `--ink-3` |
| 操作区 `.uc-foot` | 贴底通栏操作条，保存按钮右对齐 | 负边距通栏 + 1px 上分隔 + `#fcfcfd` 底 |

- 用户名只读字段用 `.uc-ro`（静态值 + 锁图标 + 浅灰底），不使用 `disabled` 输入框——禁用态的灰字无法区分「不可编辑」与「加载失败」
- 头像整圆可点，悬停显示 52% 深色遮罩与换图图标；`:focus-visible` 有品牌色描边，键盘可操作
- 页面不常驻格式与体积说明：校验在选图时即时执行，仅失败时以 toast 反馈
- 侧栏导航 `.uc-nav` 选中态为圆角胶囊（`--brand-l2` 底 + 品牌色字）；≤900px 转为横向滚动胶囊条，不再纵向占满首屏

### 2.7 消息提醒（角标）

单一数字 `store.pending`，按角色与所在层级决定显示位置：

| 角色 | 含义 | 页面外 | 页面内 |
|---|---|---|---|
| 管理员 | 待发货数（status=1） | 页头头像角标 + 下拉「后台管理」 | 侧边栏「订单管理」 |
| 普通用户 | 待收货数（status=2） | 页头头像角标 + 下拉「我的订单」 | 订单页「待收货」标签 |

任何时刻只显示一个角标，始终指向当前最该点击的位置。

> 私信未读不参与上述 `store.pending` 逻辑：它使用头像左上角的蓝色小点独立提示，语义与订单待办分开，见 2.10。

### 2.8 界面图标体系

全站不再使用系统 emoji 做区分标识。emoji 在不同平台渲染为彩色 3D 字形，线宽、透视、配色无法统一，是界面"质感粗糙"的主要来源，故统一改为手写线性 SVG。

| 项 | 规格 |
|---|---|
| 网格 | 24 × 24，主体图形落在 2–21 视觉安全区 |
| 描边 | 1.7px，圆角端点与圆角连接，只用描边不用填充 |
| 着色 | `stroke="currentColor"`，颜色继承父级 |
| 图标数 | 36 个，注册在 `DH.icons` |
| 调用 | `<ui-icon name="cart" :size="18">`，内联 SVG，无外部请求 |

颜色继承是该体系的关键设计：同一套图标在白色页头呈深灰、在深色后台侧栏自动转白、选中态转纯白，无需为两套配色维护两份资源。

覆盖范围：页头（搜索 / 购物车 / 登录）、用户下拉菜单、后台侧栏、个人中心菜单、商品详情按钮与服务标签、结算支付方式、首页秒杀标题与促销位角标、各页面空状态、订单状态图例、我的订单筛选标签。

轻提示（toast）采用**渲染层映射**：调用方仍传 `✅` / `⚠️` 等状态字符，`TOAST_ICON` 表（14 条映射）在渲染时转为对应线性图标，44 处调用点无需改动。

### 2.9 首页视觉规范（场景图卡）

首页三个区块采用「图先声夺人」的场景图卡语言。视觉规则集中在本节，替换素材或调整控件时以此为准，不必回查提交历史。

#### 模块外壳（`.sec-card`）

首页四个内容模块（服务承诺、全部分类、限时秒杀、为你推荐）各自包在统一的外壳模板里，成为独立视觉单元，不再裸贴在页面主背景上：

| 属性 | 值 | 说明 |
|---|---|---|
| 背景 | `#fff` | 秒杀深色场由区块自身覆盖，外壳只负责「白底托底」 |
| 圆角 | `--r-lg` | 与服务承诺条一致，整页同一曲面体系 |
| 阴影 | `--sh-1` | 最轻一级投影，与卡片层级匹配 |
| 内边距 | 20px 22px 22px | ≤600px 收窄为 15px 14px 16px |
| 区块头分隔 | 底部 1px `--line-2`，下含 18px 间距 | 标题区与内容区在壳内分隔 |
| 模块间距 | 统一 16px（≤600px 为 12px） | 四块曲面节奏一致 |

壳内控件跟进两条边界规则：分类入口卡加 `outline: 1px solid rgba(9,11,16,.06)`（offset -1px）防止白卡贴白卡；推荐商品卡加 1px `--line-2` 边框，同一逻辑。分类入口图标尺寸由 42px 收至 38px，保证图标底部不侵入名称文字块。

#### 区块结构与参数

| 区块 | 结构 | 关键参数 |
|---|---|---|
| 服务承诺 | 四项图标 + 文案的白色横条 | 圆角 `--r-lg`，四等分 |
| 全部分类 | 16:9 场景卡：图片铺满 + 底部渐变压暗 + 白色名称压左下 | 圆角 14px，渐变覆盖底部 46%，名称 13/600，件数 11/0.86 不透明 |
| 限时秒杀 | 深色场 + 左上品牌红径向光 + 白底商品卡 | 圆角 16px，价格 27/800，爆价贴纸斜切 12° |
| 为你推荐 | 等高栅格，图统一 1:1，卡片等宽等高 | 网格 `minmax(208px,1fr)`，间距 14px，卡片圆角 14px |

#### 控件规格

| 控件 | 类名 | 高度 | 圆角 | 字号/字重 | 视觉处理 |
|---|---|---|---|---|---|
| 区块动作按钮 | `.sec-link` | 32px | 999px | 12.5 / 500 | 白底 + 1px `--line` + `--sh-1`；悬停转品牌色、上浮 1px、箭头右移 2px |
| 展开/收起 | `.cats-btn` | 36px | 999px | 13 / 600 | 白底 + `--sh-2`，收起态压第三排中线、展开态移列表下方 |
| 常规按钮 | `.btn` | 38px（`.btn-sm` 30px） | `--r-sm` 8px | 13.5 / 500 | 用于表单、弹窗、详情页操作，**不用于区块头部** |
| 小标签 | `.tag` | 21px | 6px | 11.5 / 500 | 默认 `--line-2` 底 + `--ink-2` 字；`-brand` / `-ok` / `-warn` 为语义变体 |
| 爆价贴纸 | `.hot` | 内距 3×9 | 4px | 11 / 800 | 外框斜 -12°、内文 +12° 回正，保证文字正立 |
| 线性图标 | `.ui-ic` | 由 `:size` 决定 | — | 1.7 描边 | 24 网格，`currentColor` 继承父级色 |

区块头部与分类区共用 999px 胶囊语言；表单与弹窗仍用 8px 圆角常规按钮，两者按「浏览区 vs 操作区」分工，不混用。

#### 断点矩阵

| 视口 | 分类卡 | 秒杀卡 | 推荐卡 | 其他调整 |
|---|---|---|---|---|
| > 900px | 6 列（固定） | 4 列（固定） | `auto-fill minmax(208px,1fr)`，1200 容器下为 5 列 | — |
| ≤ 900px | 3 列（固定） | 4 列（固定） | 同上规则，760px 实测 3 列 | 价格降到 24px |
| ≤ 600px | 2 列（固定） | 2 列（固定） | `auto-fill minmax(160px,1fr)`，390px 实测 2 列 | 卡片圆角 12px、名称 12px、价格 22px、加购按钮常显 |

分类与秒杀用固定列数，推荐区用 `auto-fill` 流体列数——前者卡片内容固定、换行会影响折叠计算，后者需要随容器宽度自然增减。

#### 实施约定

- 分类卡无封面时不显示空白，改用「色相渐变 + 分类图标」兜底，保证未配图也不塌陷
- 分类名与件数压在图上，因此封面素材**不要自带标题文案**，否则会与叠字冲突
- 秒杀价不做划线原价——`product` 表没有原价字段，凭空计算会误导买家
- 首页推荐区为等高栅格；列表页、详情页推荐、购物车推荐共用同一套 `.goods` 栅格规则
- 商品卡（`goods-card`）价格与销量同行（价格左加粗、销量右对齐）、缺货/仅剩用图片角标而非文字区标签、加购按钮为 `cart` 线性图标；缺货商品图片降饱和，弱化可购买预期
- 断点全部靠 CSS 媒体查询，无 JS 参与；分类区折叠高度由运行时实测，随列数变化自动重算
- 悬停类效果（上浮、箭头位移、图片放大）均在 `≤600px` 下失效或改为常显，适配触屏

### 2.10 社交关注与私信

商品详情页承担"从商品到人"的入口：展示发布者、可关注、可直接发起会话。

#### 关注

- 详情页卖家卡展示头像、昵称、粉丝数，提供「关注 / 已关注」与「发消息」两个动作
- 关注为幂等操作，重复关注不报错；取消未关注的关系同样返回成功
- 不能关注自己（`3001`）；未登录点击关注或发消息会跳转登录页
- 商品 `seller_id` 为空时表示平台自营，卡片显示「东华自营」，**不提供关注与「发消息」按钮**；
  整张卡片本身就是会话入口，点击后与平台官方账号（`role=1` 且状态正常的第一个账号）建立会话，右侧以「联系官方客服 →」作指引
- 官方账号由后端在卖家摘要里以 `serviceUserId` 下发；站点若没有可用的管理员账号，该字段为空，前端提示「官方客服暂不可用」而不跳转
- 当前登录的就是官方账号时，卡片不显示跳转指引，点击提示「当前登录的正是官方账号」，避免自己与自己建会话（后端 `3004` 兜底）
- 关注列表与粉丝列表均实时显示「互相关注」标记：关注列表中该标记表示"对方也关注了我"，粉丝列表中表示"我已回关"

#### 私信

会话模型的关键约束：**两个用户之间只有一条会话**。写入前把用户 ID 排序归一化为 `user1_id < user2_id`，配合唯一键保证并发下也只产生一条。

| 能力 | 说明 |
|---|---|
| 会话创建 | `POST /api/conversations` 幂等：存在则返回原会话，不存在则创建 |
| 消息类型 | `type=1` 纯文字（≤1000 字）；`type=2` 图片（复用 `POST /api/common/upload` 拿到地址后发送） |
| 表情 | 输入框内置 24 个常用 emoji 的选择面板，点击插入文本，不引入第三方库 |
| 实时推送 | WebSocket `/ws/chat?token=<JWT>`，仅下行；发送仍走 REST，落库成功后再推送 |
| 断线兜底 | 通道断开时按 1/2/4/8/15 秒退避重连；重连后用 `afterId` 增量补齐 |
| 已读 | 打开会话即标记该会话中发给我的消息为已读，返回我的未读总数 |
| 未读角标 | 独立于订单待办：页头头像左上角蓝点、下拉菜单「消息」数字、个人中心身份卡「消息」格 |

- 越权防护：所有 `/conversations/{id}/**` 均在服务层校验当前用户是会话参与者，「不存在」与「无权访问」统一返回 `3002`，避免用 id 探测他人会话
- 图片消息只接受站内产物（`/uploads/` 或本桶 OSS 域名），否则返回 `3006`
- 页头头像的蓝点与右侧订单角标分处头像两端，两种语义互不覆盖

#### 个人中心

### 2.11 交易链路

交易部分按「金额 → 支付 → 状态 → 售后」四层拆分，每层只有一个权威出口。

#### 购物车

购物车与结算的衔接点只有一个：`checked = 1` 的行。围绕这一点有三层约束。

| 约束 | 实现 |
|---|---|
| 一人一商品仅一行 | `cart_item` 唯一键 `uk_user_product (user_id, product_id)`，加购走 `INSERT ... ON DUPLICATE KEY UPDATE`，并发或连点不会产生重复行 |
| 数量不超卖 | 加购与改数量都以「当前库存」为上限封顶，由后端校验，不依赖前端控件 |
| 失效商品隔离 | 列表返回商品 `status`，已删除 / 已下架 / 售罄的行置灰、不可勾选、不计入合计，并提供「清空失效」；全选只作用于可售行 |
| 失效商品不参与结算 | 取待结算行时联表过滤「勾选 + 在售 + 有库存」，失效行既不计入金额，也不会把整笔订单卡在「不可购买」；结算页以 `notice` 告知被排除的件数 |

历史数据中同一商品的多行由迁移 `migration_10_cart.sql` 合并（保留最早一行、数量累加后按库存封顶），随后建立唯一键。

#### 商品来源：购物车与立即购买

结算页支持两种商品来源，二者共用同一套算价、扣库存与快照逻辑（`OrderService.resolveLines`），差异只在明细从哪来：

| 来源 | 入口 | 行为 |
|---|---|---|
| 购物车 | `#/checkout` | 结算全部 `checked=1` 的行，下单成功后删除这些行 |
| 立即购买 | `#/checkout?buy={productId}&qty={n}` | 只结算该商品，不写入也不删除购物车，不受购物车勾选状态影响 |

直购的意义在于语义正确：此前的实现是「静默加购后跳结算」，会把用户购物车里其他已勾选商品一并买下，并污染购物车。

#### 金额口径

`PricingService` 是全站唯一的金额计算器，**结算试算与真实下单调用同一个方法**，前端不做任何金额推算。

| 项 | 规则 |
|---|---|
| 商品金额 | 服务端按商品当前单价 × 数量重算，不信任前端传值 |
| 运费 | 商品金额未达门槛收固定运费，达到门槛免运费（`shop.freight.fee=10` / `free-threshold=99`） |
| 优惠 | 满减券：需满足门槛与适用范围，抵扣额不超过适用商品金额，避免负数订单 |
| 应付 | `商品金额 + 运费 − 优惠`，落库到 `orders.pay_amount`，`total_price` 同步为该值 |

#### 结算页

进入 `#/checkout` 先调 `GET /api/orders/preview`，返回三样东西：商品可购买性（下架 / 库存不足会给出具体提示并禁用提交）、价格明细、以及**我的券（含不可用项与原因）**。切换优惠券会重新试算，金额变化即时反映。

#### 下单幂等

进入结算页时领取一次性 `submitToken`（落 `order_submit_token` 表），提交时回传。

- 同一令牌重复提交：服务端查到已消费的令牌，直接返回**原来那笔订单**，前端视为成功
- 并发提交：`consume` 是条件更新（`WHERE status = 0`），抢输的一方整笔回滚
- 未带令牌的旧调用仍可通过，但新前端一律携带

#### 支付

下单与支付分离：下单只产生「待付款」订单并写入 `expire_at`，支付走独立支付单。

| 步骤 | 说明 |
|---|---|
| 创建支付单 | `POST /api/payments`，同订单同渠道复用未关闭的支付单 |
| 收银台 | `#/pay/{orderNo}`，倒计时取自 `orders.expire_at`，超时禁用支付入口 |
| 回调 | `POST /api/payments/{no}/mock-callback` 模拟三方异步通知，`markSuccess` 用条件更新保证只生效一次 |
| 推进订单 | 回调成功后才 `0→1`；若订单已被关单，整笔回滚并提示已关闭 |
| 重复支付 | 订单已是待发货时创建支付单直接返回 `3017` |

货到付款不走支付单，下单即进入待发货。

#### 售后

用户对 1/2/3 状态的订单可申请售后，订单转入「退款中」冻结状态；管理员在后台「售后审核」通过后订单转「退款完成」并回补库存，拒绝则按时间戳推导回原状态（发货前→待发货，发货后→待收货，完成后→已完成），无需额外存原状态。

#### 异常场景

| 场景 | 处理 |
|---|---|
| 库存不足 | 下单用 `stock >= qty` 条件更新扣减，失败即整笔回滚并提示具体商品剩余量 |
| 商品下架 | 试算阶段即标记不可购买并禁用提交；下单时再次校验 |
| 支付超时 | 定时任务每分钟扫描 `status=0 且 expire_at <= now`，关单并回补库存、退回优惠券、关闭支付单 |
| 重复提交 | 一次性令牌 + 条件更新消费 |
| 并发状态变更 | 所有迁移走 `UPDATE ... WHERE status = 旧值`，影响行数为 0 即视为冲突 |
| 超时未收货 | 发货 7 天后自动确认收货（每日凌晨执行） |

### 订单状态

| 状态 | 含义 | 触发方 |
|---|---|---|
| 0 | 待付款 | 下单后，超时由定时任务关闭 |
| 1 | 待发货 | 支付回调成功（货到付款下单即进入） |
| 2 | 待收货 | 管理员发货 |
| 3 | 已完成 | 用户确认收货，或发货 7 天后自动确认 |
| 4 | 已取消 | 用户取消（归还库存、退回优惠券） |
| 5 | 已关闭 | 超时未支付，系统自动关闭 |
| 6 | 退款中 | 售后申请提交后冻结订单 |
| 7 | 退款完成 | 售后审核通过（归还库存） |

状态迁移只允许下列边，其余一律拒绝：`0→1/4/5`、`1→2/6`、`2→3/6`、`3→6`、`6→7`，以及售后被拒时 `6→原状态`。

| 状态 | 含义 |
|---|---|
| 0 | 待审核 |
| 1 | 审核通过（已生成正式商品） |
| 2 | 审核拒绝（含拒绝原因） |

## 八、图片上传设计

### 校验规则（前后端双重）

1. 单张 ≤ 5MB
2. 仅支持 `jpg / jpeg / png / webp`
3. 服务端校验 `Content-Type`
4. 文件名使用 **UUID 重命名**，不直接使用用户文件名
5. 本地存储额外做路径穿越防护

### 存储模式

| 模式 | 配置 | 访问方式 |
|---|---|---|
| 本地磁盘（默认回退） | `storage.type=local` | `/uploads/...` 静态映射 |
| 阿里云 OSS | `storage.type=oss` + 密钥 | OSS 公网 URL |

OSS 对象路径：`product/{yyyy}/{MM}/{uuid}.{ext}`

> Bucket 需设置为「公共读」，否则图片 URL 会返回 403。

## 十二、已知限制与后续规划

### 当前限制

- 消息提醒为**拉取式**（登录/操作后刷新），无 WebSocket 实时推送
- 轮播图按上传顺序展示，暂不支持拖拽排序
- 分类删除只校验商品占用，未校验子分类（当前分类均为顶级）
- 促销位图片未做比例校验，非 1.9:1 的素材会被裁切
- 移动端 390px 下页头导航存在横向溢出，尚未收纳为抽屉菜单
- 商品申请/商品列表未做全文检索，使用 `LIKE`
- 单机部署，未引入缓存与消息队列
- 商品无图时统一显示 `box` 线性图标，不再按分类用 emoji 区分，失去了色彩区分度
- 图标为内联 SVG，只能由代码增补，未做成可后台配置的资源
- 秒杀位无独立秒杀价与限时结束时间，仅做展示位编排
- 分类封面需运营逐个上传，未上传的分类只能显示色相渐变兜底
- 秒杀卡不做划线原价，因 `product` 表缺少原价字段，需补列才能显示
- 私信的 WebSocket 在线连接表为**单机内存实现**，多实例部署需替换为 Redis 广播，否则跨实例收不到推送
- 反向代理部署时需放行 `Upgrade` / `Connection` 头，否则 `/ws/chat` 握手会退化为长轮询失败（前端会自动回退到增量轮询）
- 私信入口只开放「商品详情页卖家卡」与「关注 / 粉丝列表」，不支持按用户名搜索任意用户发起会话
- 支付为**模拟网关**：收银台点确认后本地触发回调，未对接真实三方支付与退款通道
- 定时任务为单机执行（`@Scheduled`），多实例部署会重复跑关单与自动收货，需引入分布式锁或调度中心
- 运费为统一费率，未做按地区、重量、件数的差异化计算
- 优惠券仅支持满减，不支持折扣券、多券叠加与按商品分摊优惠金额
- 退款为整单退款，暂不支持按订单明细部分退款与退货物流回填

### 可扩展方向

- 我的商品（按 `seller_id` 展示用户自己上架的商品）
- WebSocket / SSE 实现订单与审核实时通知
- 图片拖拽排序、图片压缩、CDN 加速
- Redis 缓存热点商品、秒杀限流
- 订单超时自动取消（定时任务）
- 支付对接真实第三方支付
- 单元测试与接口自动化测试

## 十三、安全说明

- 密码使用 BCrypt 加密存储，接口不返回密码字段
- JWT 密钥与数据库密码、OSS AccessKey 均放在 `application-local.properties` 或环境变量，不进入仓库
- 上传接口做大小、格式、Content-Type、UUID 重命名、路径穿越多重校验
- 后台接口统一 `@RequireAdmin`，服务端校验角色，不依赖前端隐藏按钮
- 商品详情按纯文本渲染，避免存储型 XSS
